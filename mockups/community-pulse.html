Frontend / Home map overlay

Community Pulse — Redesign Mockups

The current overlay has two problems: a single small stat ("Active Reports") sits awkwardly next to a heavy 48 px icon, and the 84% resolution rate is a hard-coded string. Below: the current state for reference, three redesign options, and the data wiring each one needs. All sample numbers come from the same hypothetical dataset of 30 reports citywide (8 pending, 14 verified, 8 fixed). The current frontend doesn't viewport-filter the report list — see the recommendation section for the optional upgrade that makes these numbers update as you pan the map.

Why it reads as off

  • A 48 px icon tile sits next to a single line of text — the row reads as half-empty and visually unbalanced.
  • The headline statistic uses text-xs, smaller than the card's own title above it.
  • "Active Reports" displays reports.length — that includes fixed and rejected reports too, contradicting the label.
  • 84% is a literal string, not derived from any field on the report objects. Two reports in, three reports out — number never moves.

What changes & why

  • Two equal-weight tiles replace the awkward icon-and-text row — the layout now reads as a deliberate dashboard, not a half-built widget.
  • Numbers jump from text-xs to text-2xl, the headline-font weight matches the card title, and labels move below the value for proper hierarchy.
  • "Active" now means what it sounds like (pending + verified obstacles); "Fixed" celebrates the community win.
  • Resolution rate becomes fixed ÷ (fixed + active), recalculates on every SSE update, and a sub-caption tells you the underlying numbers so the bar is auditable.
Data wiring 
const obstacles = reports.filter(r => r.reportType === 'OBSTACLE')
const active = obstacles.filter(r => r.status === 'PENDING' || r.status === 'VERIFIED').length
const fixed  = obstacles.filter(r => r.status === 'FIXED').length
const denom  = active + fixed
const resolutionPct = denom ? Math.round((fixed / denom) * 100) : 0

What changes & why

  • One big hero number anchors the card — eye lands on it instantly, no competition with the icon row.
  • Three small dot-chips give the status split without needing three tiles' worth of real estate.
  • Best fit if you want the card to tell a story at a glance rather than read as a multi-KPI dashboard. Trade-off: the "Fixed" count is demoted from a headline to a chip.

Same data wiring as Variant A; the chips just expose the underlying status breakdown.

What changes & why

  • A single proportional bar shows the lifecycle of nearby reports — readers can see at a glance whether the area skews "lots of pending unverified noise" vs. "mostly verified, slow to fix."
  • Most analytically dense of the three options; closest to a status-tracking dashboard.
  • Trade-off: needs slightly more vertical space, and the bar can be hard to parse on the smallest screens (we already hide the card below lg so this is mostly fine).

My recommendation

Ship Variant A. It directly addresses both reported issues:

  1. The "out of place" feeling comes from the asymmetric icon-vs-text row. Two equal stat tiles make the layout deliberately balanced, and the bigger numbers give the card the visual weight a floating overlay deserves.
  2. The hardcoded 84% becomes a derived value with the data wiring shown above — a one-liner over reports, no API changes needed. It will live-update through the existing useSseSync path.

Variant B is a strong fallback if the team prefers a one-glance card; Variant C is a good fit if you want to push the home page closer to an analytics surface, but it's the heaviest of the three. Happy to wire up whichever you pick — say the word.

map Optional upgrade: make the numbers viewport-scoped

Today useReports() returns the full citywide list — no map-bounds filter exists in the frontend. As a follow-up (~15 lines on Home.jsx), we can track map.getBounds() on the existing moveend handler and filter the array before counting. The card then becomes a live "pulse of what you're looking at" — numbers tick as the user pans. Worth doing because the card literally sits on the map.
